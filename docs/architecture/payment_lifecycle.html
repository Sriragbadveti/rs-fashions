RS Fashions — Payment Lifecycle

Cashfree payment integration · POS billing flow · Webhook state machine · Based on actual source code

🛒 Mode 1: Online Storefront Checkout

1
Customer proceeds to checkout
Checkout.tsx — Address form filled. Payment method selected (Cashfree is default).
2
Generate stable order number
stableOrderNumberRef — useRef ensures same order number on re-renders; prevents accidental duplicate orders
orderNumber = "RSF-" + timestamp.toString(36).toUpperCase()
3
Record pending sale
POST /api/billing/pos-checkout — Saves order to Supabase orders table with payment_status: 'pending'
{ items, address, total, paymentMethod: 'cashfree', paymentStatus: 'pending', billingType: 'online' }
4
Create Cashfree order
POST /api/payments/cashfree/create-order — Backend calls Cashfree API. Returns payment_session_id.
POST https://api.cashfree.com/pg/orders Headers: x-client-id, x-client-secret, x-api-version → Returns: { payment_session_id: "session_..." }
5
Load Cashfree SDK
loadCashfreeScript() — Dynamically adds script tag to DOM. Checks if already loaded to avoid duplicates.
src="https://sdk.cashfree.com/js/v3/cashfree.js"
6
Open payment modal
Cashfree SDK — Customer sees UPI, credit/debit cards, net banking, wallets options.
const cashfree = Cashfree({ mode: "production" }); cashfree.checkout({ paymentSessionId: session_id, redirectTarget: "_modal" });
7
Cashfree redirect after payment
Cashfree redirects to: /checkout?order_id=RSF_...&status=cashfree_return
8
Verify payment
POST /api/payments/cashfree/verify — Backend calls Cashfree API to get payment status. Updates Supabase order if SUCCESS.
GET https://api.cashfree.com/pg/orders/:id/payments → payment_status: "SUCCESS" | "FAILED" | "PENDING"
9
Frontend completes order
clearCart() → save order to localStorage → navigate to success screen. Simultaneously: Cashfree webhook fires to update order asynchronously.

🏪 Mode 2: POS Counter Billing (Payment Link)

1
Admin opens Billing.tsx
Billing.tsx — Admin selects products, enters customer name, phone, email. Invoice generated with GST breakdown.
2
Generate payment link
POST /api/payments/cashfree/create-payment-link
{ invoiceNumber, amountInRupees, customerName, customerPhone, customerEmail, items, subtotal, discount, total, billingType: 'pos' }
3
Duplicate prevention (distributed lock)
payments.controller.js → acquireLock(posKey) — Prevents race condition if admin clicks "Generate" twice. If PENDING link already exists → reuses it.
✓ If link already exists and is PENDING: reuses existing link (no duplicate order)
4
Backend creates Cashfree order
cashfree.service.js → createCashfreeOrder() — Creates Cashfree order. Generates custom payment link URL pointing to /pay route.
paymentLink = `${clientUrl}/pay?order_id=${orderId} &session_id=${payment_session_id} &amount=${amount}&invoice=${inv} &customer=${customerName}`
5
Admin shares payment link
Link copied → shared via WhatsApp, SMS, or displayed as QR code. Customer receives link on their phone.
6
Customer opens QuickPay.tsx
QuickPay.tsx — Route: /pay. Reads URL params: order_id, session_id, amount, invoice, customer. Shows amount and invoice details.
7
Check if already paid (on mount)
POST /api/payments/cashfree/verify — If already PAID → shows success screen immediately. Prevents re-payment of same invoice.
8
Customer pays
Cashfree SDK — Same Cashfree JS SDK v3 loaded. Customer pays using session_id from URL params.
9
Webhook auto-records sale
handleCashfreeWebhook → autoRecordPosSale() — When POS payment succeeds, automatically creates sale record in Supabase orders table, deducts stock, updates CRM.
✓ Stock deduction + sale recording happens automatically via webhook — no manual action needed

⚙️ Cashfree Webhook Handler (handleCashfreeWebhook)

1
Signature Verification (HMAC-SHA256)
dataToSign = x-webhook-timestamp + JSON.stringify(body) computedSig = HMAC-SHA256(dataToSign, CASHFREE_SECRET_KEY) assert computedSig === x-webhook-signature
✓ Prevents spoofed webhooks from attackers
2
Idempotency Check
eventId = cf_payment_id || event_id || computed if (isWebhookEventProcessed(eventId)) { return 200; // Already handled, ignore }
✓ Cashfree may send same event multiple times — safe to ignore duplicates
3
State Machine Transition
if (paymentStatus === "SUCCESS") { // Check not already PAID first markOrderPaidInStore(cfOrderId); supabase.from('orders').update({payment_status: 'paid'}) autoRecordPosSale(cfOrderId); // If POS order } if (paymentStatus === "FAILED" || "CANCELLED" || "EXPIRED") { // Check if already PAID — if so, SKIP (protect PAID state) updatePaymentAttemptStatus(cfOrderId, paymentStatus); }
4
Mark Event as Processed
recordWebhookEvent(eventId, { cfOrderId, eventType, paymentStatus }); // Writes to webhook_events.json (persistent across requests)
✓ Even after server restart, already-processed events won't be re-handled

Persistence Points

📁 webhook_events.json — processed event IDs for deduplication
📁 orders.json — local order state mirror
🗄️ Supabase orders table — payment_status updated on SUCCESS
🗄️ Supabase stock_movements — stock deduction audit trail
🗄️ Supabase customers — total_spent + orders_count updated
