RS Fashions — Backend MVC Request Flow

Express server · Route definition · Controller logic · Data persistence

1. Express Setup

server.js

Entry point. Initializes Express app on port 5001.

Middleware Chain

1. CORS

Whitelists origins (with permissive fallback bug)

2. express.json

Body parser with 50MB limit

3. requestLogger

Logs HTTP method + URL

2. Routing Layer

routes/index.js

Central router. Defines the split between public and protected routes.

Public Routes

Mounted directly onto apiRouter. No auth required.

/api/catalog/*
/api/payments/*
/api/auth/*
/api/billing/pos-checkout

Protected Routes

Wrapped in requireAdminAuth middleware.

/api/admin/catalog/*
/api/admin/inventory/*
/api/admin/bootstrap/*

⚠️ Arch. issue: Routes are triple-mounted.

3. Controllers (Logic)

catalog.controller.js

getProducts()

Memory cache → Supabase → localStore

createProduct()

Validates → auto-uploads images → Supabase INSERT

payments.controller.js

createCashfreePaymentLink()

Distributed lock → Cashfree API call

handleCashfreeWebhook()

HMAC verify → Idempotency → State Machine

auth.controller.js

adminLogin()

Loads admins → crypto.scryptSync → Custom JWT

4. Data Access

config/supabase.js

Two clients: adminClient (service-role) + publicClient (anon).

Tables: products, orders, stock_movements, settings, customers

database/localStore.js

File-based JSON persistence. Used as fallback when Supabase is offline.
