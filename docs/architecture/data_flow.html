RS Fashions — Data Flow Diagram

Where data comes from, where it goes, and how it persists · Based on actual source code

Data Persistence Strategy: Dual-Write Pattern

RS Fashions uses a dual-write + dual-read pattern for resilience. Every write operation goes to Supabase (primary) AND to a local JSON file (fallback). Every read tries Supabase first; if unavailable or returning error, reads from the JSON file. This means the system continues operating — even in read/write mode — when Supabase is unreachable. The risk: data can drift out of sync if network issues occur during a write.

Operation Primary (Supabase) Fallback (localStore) Notes
Read products Memory cache → Supabase products.json Cache TTL: 5 min. Merged with variants from settings.
Write product Supabase products table products.json Both written on create/update/delete. Cache invalidated after write.
Read orders Supabase orders table orders.json Admin order list, customer order history.
Write order Supabase orders table orders.json Created on checkout; updated on payment confirmation.
Read admin accounts Supabase settings (admin_accounts) admin_accounts.json (gitignored) Cached in memory for 5 min. Deleted admin can auth for up to 5 min.
Read product variants Supabase settings (product_variants) None One JSON blob. Not queryable per-product. Merged in getProducts.
Webhook idempotency None webhook_events.json Deduplication persists across restarts. Does NOT live in Supabase.
Payment attempts None payment_attempts.json Tracks POS payment link status per invoice key.
Stock movements Supabase stock_movements table None Immutable audit trail. Not written to localStore.
Customer session None localStorage (browser) No server validation on subsequent requests. 30-day expiry.
Admin session token activeAdminSessions Map (in-memory) localStorage (browser) Token validated server-side on every /api/admin/* request.
Cart items None localStorage (browser) CartContext loads from 'rs_fashions_cart' on mount. No expiry.
Order fulfillment Backend PUT /sales/:inv/fulfillment localStorage (browser) 4 localStorage keys updated synchronously: rs_order_fulfillments, rs_fashions_orders, rs_admin_sales_history, rs_admin_sales.

Supabase settings Table Keys

The settings table functions as a key-value store for all configuration and dynamic data

KeyValue TypeContent
admin_accounts JSON Array Admin records with scrypt-hashed passwords. Loaded on every login. Cached 5 min.
color_palette JSON Array [{name, code, slug}] — All registered fabric colors. Used in product forms and catalog.
product_variants JSON Object {"product-id": [{sku, color, colorSlug, stock}]}. All variants as one blob. Merged during getProducts.
store_info JSON Object Business name, address, GST number, contact info. Used for invoice generation.
sale_config JSON Object Sale event configuration (start/end dates, discount rules for for_sale products).
⚠️ Architectural Issue: Three very different types of data share the same settings table — authentication credentials (admin_accounts), product data (product_variants), and UI configuration (color_palette). This works at small scale but creates security and query concerns.
