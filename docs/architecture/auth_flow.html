RS Fashions — Authentication Flow Diagrams

Admin JWT-like token system · Customer Google OAuth · Based on actual source code

🔐 Admin Login Flow

1
Admin fills login form
Login.tsx — Collects email + password
2
POST /api/auth/admin-login
auth.controller.js → adminLogin()
Body: { email, password }
3
Load admin accounts
admin.service.js → getAuthorizedAdmins() — Tries Supabase settings(key: admin_accounts) first, falls back to admin_accounts.json (gitignored)
4
Verify password
admin.service.js → verifyPassword()
crypto.scryptSync(password, salt, 64) crypto.timingSafeEqual(stored, derived)
Legacy fallback: plain-text check against ADMIN_PASSWORD env var (then upgrades to scrypt)
5
Generate token
adminAuth.js → generateAdminToken()
TOKEN = base64url(header) + "." + base64url({role:"admin", exp:+24h, jti}) + "." + HMAC-SHA256(header.claims, AUTH_SECRET)
⚠️ AUTH_SECRET falls back to hardcoded string if env vars missing!
6
Store token in browser
adminSession.ts → saveAdminSession() — Saves to localStorage key 'rs_admin_session'
7
Admin dashboard loads
Admin.tsx → useEffect — Immediately calls GET /api/auth/admin-verify to validate token against server. If invalid → clears session → shows Login.
8
Protected API requests
requireAdminAuth middleware — Every /api/admin/* request: extracts Bearer token → verifyAdminToken() → checks revokedTokens Set → verifies HMAC → checks exp → checks role:'admin' → attaches req.adminUser
9
Logout
auth.controller.js → adminLogout() — Adds token to in-memory revokedTokens Set
⚠️ revokedTokens is in-memory only. Server restart clears it — revoked tokens become valid again for up to 24 hours!

🔑 Customer Google OAuth Flow

1
Customer clicks "Sign in with Google"
Auth.tsx — Renders Google OAuth button
2
Google OAuth redirect
Browser redirected to accounts.google.com consent screen. User grants permission.
3
Google callback
AuthCallback.tsx — Receives authorization code or ID token from Google redirect to /auth/callback
4
Verify Google token with backend
POST /api/auth/google/verify
Body: { credential: googleIdToken }
5
Backend verifies with Google
auth.controller.js → verifyGoogleToken() — Calls oauth2.googleapis.com/tokeninfo?id_token=...
⚠️ tokeninfo is Google's debug endpoint — use google-auth-library in production
6
Upsert customer record
auth.controller.js — Checks Supabase customers table by email. Creates new record if first login, updates name if returning user.
supabase.from('customers').upsert({ email, name, google_id, auth_provider: 'google' })
7
Return user payload
Backend returns: { id, name, email, role:'user', authProvider:'google', avatarUrl }
8
Store customer session
userSession.ts → saveUserSession() — Saved to localStorage 'rs_user_session' with 30-day expiry
⚠️ No server-side session validation for customers on subsequent requests — purely client-side
9
Customer accesses protected features
Checkout, Account page, saved addresses all read from userSession.ts. Session expires after 30 days or when browser storage is cleared.

🔑 Admin Account Management

1
Admin accounts are stored in Supabase
Settings table, key: 'admin_accounts', value: JSON array of admin objects with scrypt-hashed passwords
[{ id, name, email, passwordHash: "salt:key", isPrimary: true/false, createdAt, lastLoginAt }]
2
Primary admin auto-seeded from env vars
If no admins found → buildDefaultPrimaryAdmin() using ADMIN_EMAIL + ADMIN_PASSWORD env vars. Primary admin can never be deleted.
3
Create new admin (authorized)
POST /api/auth/admin-create-authorized — Requires master admin email + password in body. OR POST /api/admin/admins (requires valid Bearer token).
4
Admin cache TTL
Admin accounts cached in memory for 5 minutes. Deleted admin can still authenticate for up to 5 minutes.
⚠️ Cache is in-memory per process — not shared across Render instances

🛡️ Token Structure (Custom JWT-like)

// Header
base64url({ "alg": "HS256", "typ": "JWT" })
// Claims (Payload)
base64url({
  id: "admin-id",
  name: "Sindhuja",
  email: "admin@rsfashions.in",
  role: "admin", // Required!
  isPrimary: true,
  iat: <unix timestamp>, // Issued at
  exp: iat + 86400, // 24 hours
  jti: "adm_1234_abc" // Unique ID
})
// Signature
HMAC-SHA256(header + "." + claims, AUTH_SECRET)
✓
Verification checks (in order)
1. Is token in revokedTokens Set? → REJECT
2. Split by "." → 3 parts? → else REJECT
3. Recompute HMAC → timingSafeEqual() → mismatch? REJECT
4. Decode claims → check exp > now → expired? REJECT
5. Check claims.role === 'admin' → else REJECT
6. Attach claims to req.adminUser → ALLOW
⚠️
Security considerations
AUTH_SECRET fallback to Cashfree secret or hardcoded string. Token revocation lost on server restart. No refresh token mechanism. Single-factor only (no OTP/MFA).
